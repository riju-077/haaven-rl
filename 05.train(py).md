# Step 5: metrics.py, train.py, backtest.py

**In short:**
- **train.py** = practice (2020–2021), with a **practice exam** (2022) after every round
- **backtest.py** = the real exam (2023–2024, years the agent has never seen)
- **metrics.py** = marks the exam

How to run (from the project folder, **one at a time**: the backtest needs the model that training saves):
```
uv run python -m scripts.train      # creates artifacts/model.pth
uv run python -m scripts.backtest   # creates artifacts/results.json
```

---

## 0. The three time periods (data.py)

| Period | Dates | Used for | School version |
|---|---|---|---|
| train | 2020–2021 | the agent learns from it | homework |
| val | 2022 | picking which saved brain to keep | practice exam |
| test | 2023–2024 | the final score, used only once | real exam |

**`prepare_data()`** gets all three ready in exactly the same way:
1. Download the prices.
2. Work out daily % returns on **all** prices first, then split. (If we split first, the first day of each period would have no "yesterday" and would show a fake 0% move.)
3. Learn the "usual move" (std) from **train only**. Using later years would be peeking at the future.
4. Return `{"train": (prices, scaled), "val": (...), "test": (...)}`.

---

## 1. metrics.py: the report card

Input: the portfolio value on each day, e.g. `[100000, 110000, 99000, 120000]`.

| Function | Meaning | Example with the list above |
|---|---|---|
| `total_return` | How much the money grew, in % | 1,20,000 / 1,00,000 − 1 = **20%** |
| `max_drawdown` | The worst fall from a high point to a later low | The peak was 1,10,000, then it fell to 99,000. 11,000 / 1,10,000 = **10%** |
| `sharpe_ratio` | Growth per unit of bumpiness, per year | Two agents both make 20%. The steady one gets a higher Sharpe |
| `summary` | All of the above in one dict | `{'final_value': 120000, 'total_return_pct': 20.0, 'max_drawdown_pct': 10.0, ...}` |

**How max drawdown works:** for each day, remember the highest value seen so far (the "peak"). The fall that day is (peak − today) / peak. Max drawdown is the biggest of those falls.
- The old notebook got this wrong. It used (max − min) / max, which counts a low that came *before* the high, and that isn't a loss.

**How Sharpe works:** take the daily % changes. Divide their average by their std (how much they jump around), then multiply by √252 (252 trading days in a year) to get a yearly figure.
- Rough guide: below 0.5 is poor, about 1 is good, 2 or more is very good.
- We assume a risk-free rate of 0 to keep it simple.

## 2. env.py additions

**`play(env, choose)`:** plays one full game with **no learning** and returns the dates, the value on each day and the baskets picked. `choose` is "who decides":
- `lambda obs: agent.act(obs, greedy=True)` means the trained brain decides.
- `lambda obs: 0` means always basket 0 (the baseline).

Both train.py (for the practice exam) and backtest.py (for the real exam) use this same loop, so every comparison is fair.

**`SWITCH_PENALTY = 0.3`** (it was 0.1 in run 2; see the experiment log): when the agent changes basket, its **reward** gets an extra −0.3. This only changes the score it learns from. The money itself only pays the real 0.1% fee.
- Example: yesterday it held basket 0. Today it picks basket 1, and the day's move is +0.50. Its reward is 0.50 − 0.3 = **0.20**. If it had kept basket 0, there would be no penalty.
- Size check: a normal Gold day moves about ±1, so a penalty of 0.3 means "only switch if you expect a noticeably better day".
- The first pick of a game is never counted as a switch.
- **Why:** in the first run it switched 212 times in 481 days. Each switch costs about 0.08% in fees (switching 0 → 1 trades 80% of the money: 80% × 0.1%). 212 × 0.08% ≈ **17%** lost to fees.
- It's a knob: higher means fewer switches. 0 = no penalty, so the agent only feels the real fee.

## 3. train.py: practice + practice exam

```
for each of 100 episodes:
    reset → ₹1,00,000 at the start of 2020
    every day of 2020–2021:
        agent picks a basket   (random if a dice roll < epsilon, else its best guess)
        env moves one day → reward (% change after fees, minus the switch penalty)
        agent remembers the day and learns from 64 random past days
    at episode end:
        decay_epsilon()   → explore a bit less (× 0.95)
        update_target()   → copy the brain into the frozen copy
        practice exam: play 2022 greedily (no learning)
        if this is the best practice-exam score so far → save the brain to artifacts/model.pth
```

**Why the practice exam?** In the first run (trained on 2020–2022, no practice exam):
- The training score climbed to **₹2.5 lakh**, but the real exam only gave **₹1.05 lakh** (the baseline got ₹1.25 lakh).
- It had memorised the training years, like a student who memorises past papers and fails on new questions. This is called **overfitting**.
- The practice exam catches this. We keep the brain that did best on 2022 (unseen), not the one that did best on homework. That's **early stopping** (picking the best checkpoint).
- Example: episode 30 scores ₹1.10 lakh on the practice exam and episode 90 scores ₹1.02 lakh. We keep episode 30, even if episode 90 scored higher on homework.

**What epsilon looks like over time:**
- Episode 1: 0.95, so 95% of moves are random.
- Episode 14: about 0.49, so half random.
- Episode 59 onwards: 0.05, the floor.
- The old notebook decayed epsilon **every day** instead of every episode, so exploring was over by about episode 10.

**Seed = 42:** fixes the "random" numbers, so running it twice gives the same result.

**The first printed line** is the practice-exam baseline: always basket 0 on 2022 = **₹1,08,955**. If the best practice-exam score is below that, expect the agent to lose the real exam too.

## 4. backtest.py: the real exam

1. Load `model.pth`, which is the best brain from the practice exam.
2. Play 2023–2024 **once** using `act(obs, greedy=True)`. Greedy means zero random moves. (The old notebook used 0.01 here, which was a bug.)
3. Play the same years with the baseline: always basket 0 (60% Gold).
4. Score both with `metrics.summary`.
5. Save everything to `artifacts/results.json`.

**Basket switches:** the number of days the agent changed basket.
- Example: actions `[0, 0, 1, 1, 0]` give **2** switches (0→1 and 1→0).
- The old notebook's "479 trades" was really just 479 days.

**What's in results.json:**
- `agent` / `baseline`: final value, return %, drawdown %, Sharpe (the agent also has switches)
- `daily`: one row per day with the date, agent value and baseline value (for drawing the chart later)
- `agent_actions`: the basket picked each day
- `baskets`, `test_period`: for reference

**Each period starts about 9 trading days late** (the test starts 2023-01-13): the agent needs 10 days of history to look at.

## Experiment log (what we tried, what changed, why)

**Score to beat on the real exam: ₹1,24,770** (always basket 0 on 2023–2024: return 24.77%, drawdown 4.63%, Sharpe 1.65).

### Summary table

| Run | What changed | Return | Drawdown | Sharpe | Switches | Final ₹ | Won? |
|---|---|---|---|---|---|---|---|
| 1 | first version | 5.53% | 5.65% | 0.49 | 212 | 1,05,530 | no |
| 2 | + practice exam (2022), + switch penalty 0.1 | 10.93% | 4.71% | 0.94 | 153 | 1,10,927 | no |
| 3 | switch penalty 0.1 → 0.3 | 16.98% | **3.42%** | 1.48 | 102 | 1,16,979 | no (but lower drawdown) |

### Run 1: first version
- **Setup:** train on 2020–2022, 100 episodes, keep the brain from the **last** episode, no switch penalty.
- **Training:** the value climbed from ₹85k (episode 1) to about ₹2.5 lakh (episode 55+), then flattened.
- **Result:** ₹1,05,530 on the real exam. The baseline won.
- **What went wrong:**
  1. **Overfitting.** ₹2.5 lakh on homework but only ₹1.05 lakh on new years. It memorised 2020–2022.
  2. **Too much switching.** 212 switches × about 0.08% fee ≈ 17% lost to fees.
- **Lesson:** a great training score means nothing. Only unseen data tells the truth.

### Run 2: practice exam + switch penalty 0.1
- **Changes:**
  1. Split off **2022 as a practice exam** (val). Training now uses 2020–2021 only. After every episode, test on 2022 and save only the best-scoring brain. *Fixes the overfitting.*
  2. Added **`SWITCH_PENALTY = 0.1`** to the reward. *Fixes the over-switching.*
- **Result:** ₹1,10,927. Return almost doubled (5.5% → 10.9%), Sharpe went 0.49 → 0.94, drawdown dropped 5.65% → 4.71%, switches fell 212 → 153. The baseline still won.
- **What went wrong:**
  - Gold rose strongly in 2023–2024, so the mostly-Gold basket was the best place to sit all along.
  - The agent spent 160 days in basket 1 (mostly Bond) and 44 days in basket 2 (mostly Liquid), missing part of the rise.
  - It still switched about once every 3 days.
- **Lesson:** both fixes helped, but the agent still trades too much for a market that rewarded just holding.

### Run 3: switch penalty 0.1 → 0.3 (final run)
- **Change:** `SWITCH_PENALTY` in `havenrl/env.py` went from **0.1 to 0.3**. Nothing else changed.
- **Why:** 153 switches is still a lot. A bigger penalty teaches it to stay put unless a switch is clearly worth it.
- **Prediction:** fewer switches, so fewer fees and more time in one basket.
- **Result:** ₹1,16,979. The baseline still won on money, but this is the best run by far:
  - Return 10.93% → **16.98%**, Sharpe 0.94 → **1.48**, switches 153 → **102**. The prediction was right.
  - **Max drawdown 3.42%, lower than the baseline's 4.63%.** Its worst fall was smaller, so it was the safer ride.
  - Baskets: 0 on 276 days, 1 on 160 days, 2 on 45 days.
- **Fair comparison:** return per unit of worst fall is 16.98 / 3.42 ≈ 5.0 for the agent and 24.77 / 4.63 ≈ 5.3 for the baseline. Close, but the baseline is still a bit better. So the agent was **safer, but not better overall**.
- **Lesson:** the switch penalty was the biggest single improvement (+6 points of return from one number). Trading costs matter a lot in trading RL.

### Final result (locked, no more tuning)
| | Agent | Baseline (always mostly Gold) |
|---|---|---|
| Final value | ₹1,16,979 | ₹1,24,770 |
| Return | 16.98% | 24.77% |
| Max drawdown | **3.42%** | 4.63% |
| Sharpe | 1.48 | 1.65 |

**Journey:** 5.5% → 10.9% → 17.0% return, and drawdown 5.65% → 4.71% → 3.42%, across 3 runs.

### The rule that ends the experiments
After run 3 we **stop tuning**, whatever the result.
- **Why:** every time we look at the 2023–2024 score and then change something, we're adjusting to the real exam. It's like seeing the exam questions and then studying for exactly those. After enough tries, a "win" would only mean we tuned to the test, not that the agent is good.
- **The honest way (for the future):** make decisions using the practice exam (2022) only, and look at the real exam once at the end.
- **If it still loses, it's still a good resume story:** "Built a DQN trading agent with transaction costs, validation-based model selection and a switching penalty. It reduced drawdown but did not beat a gold-heavy buy-and-hold baseline during the 2023–24 gold rally." Showing honest evaluation counts for more than a fake win.
