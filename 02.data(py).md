## `havenrl/data.py`

**Job:** get clean prices → split into train/test → normalize.

| Function | What it does | Why |
|---|---|---|
| `fetch_prices()` | Downloads Close prices for all 3 ETFs | Starting ingredients |
| `split_train_test(prices)` | Train = 2020–2022, Test = 2023–2024 | The agent must be tested on data it never saw |
| `fit_normalizer(train)` | Learns min and max **from train only** | Using test data here = **data leakage** (cheating with the future) |
| `normalize(prices, min, max)` | Scales prices to roughly 0–1 | Neural networks learn better with small numbers |

### Key decisions
- **`raw["Close"]`** → fixes the "Ticker" date bug. yfinance returns 2 header rows (`Price` and `Ticker`); taking `Close` leaves just the ticker names.
- **`[TICKERS]`** → yfinance sorts columns A–Z; this restores our order: Gold, Liquid, Bond.
- **`auto_adjust=True`** → includes dividends in the price. Liquid ETF now rises ₹808 → ₹968 instead of looking flat.
- **`.dropna()`** → keeps only days where **all 3** have a price.
- **Training starts 2020, not 2019** → the Bharat Bond ETF only began trading on **2019-12-30**.
- **`end + 1 day`** → yfinance's `end` date is *exclusive* (it stops the day before), so we add one day to include 2024-12-31.

### Actual output (checked)
- Total: **1237 days**
- Train: **746 days** (2020-01-01 → 2022-12-30)
- Test: **491 days** (2023-01-02 → 2024-12-31)

### ⚠️ Problem found → solve in `env.py`
After normalizing, **test** values range **0.86 → 2.3**, NOT 0 → 1.
Why? Prices kept rising (Gold almost doubled), so test prices are higher than anything seen in training. The agent sees numbers it never practised on.

Like a student who only practised sums up to 100 and gets 230 in the exam.

**Likely fix:** give the agent **daily % changes** instead of raw prices. A +1% day looks the same in 2020 and 2024.
