## Step 3: `env.py` (the game board)

### 1. What is it?

`env.py` is the **game** the agent plays.

- The **agent** is the player (built in step 4, `agent.py`).
- The **env** is the game: it shows the situation, takes the player's move and gives a score.

It doesn't learn anything. It's just the rules of the game.

### 2. Why do we need it?

The agent learns **only** from what the env shows it and the scores it gives.

- If the env shows the wrong information, the agent learns the wrong thing.
- If the env scores moves badly, the agent learns the wrong thing.

That's why it's the biggest step. Several old notebook bugs lived here (for example, the agent couldn't see what it was holding).

### 3. The game loop (1 day = 1 turn)

```
   ┌──────────────────────────────────────────────┐
   │ 1. Env shows the situation  (observation)    │
   │ 2. Agent picks a basket     (action)         │
   │ 3. Env moves 1 day forward  (real ₹ prices)  │
   │ 4. Env gives a score        (reward)         │
   └──────────────── repeat ──────────────────────┘
```

It repeats every day until the data runs out. One full run from first day to last day is an **episode**.

### 4. Observation: what the agent SEES

A list of **34 numbers**:

| Part | Count | Example |
|---|---|---|
| Last 10 days of scaled moves for Gold, Liquid, Bond | 10 × 3 = 30 | Gold today = 1.2 means "a bigger move than usual" |
| What it holds right now: cash, Gold, Liquid, Bond (as a share of total money) | 4 | `[0, 0.6, 0.2, 0.2]` = 60% in Gold |

- **Scaled moves** come from `data.py` (move ÷ usual move), so every asset is on the same scale.
- **Holdings** are included so the agent knows where it stands. The old notebook forgot this.

### 5. Action: what the agent DOES

Every day the agent picks **one of 3 baskets**:

| Action | Name | Gold | Liquid | Bond |
|---|---|---|---|---|
| 0 | mostly Gold | 60% | 20% | 20% |
| 1 | mostly Bond | 20% | 20% | 60% |
| 2 | mostly Liquid | 20% | 60% | 20% |

- Numbered 0, 1, 2 because Python counts from 0.
- "Mostly" means it always keeps a little of the other two, so one bad asset can't wipe you out.

### 6. Where do baskets come from?

**You don't fetch baskets.** `data.py` fetches 3 separate price lists (Gold, Liquid, Bond).

A basket is just a **rule we wrote** in `env.py` (the `BASKETS` table) that says **how to split the money**.

**Example:** ₹1,00,000 and the agent picks basket 0:
- Buy ₹60,000 of Gold at today's Gold price
- Buy ₹20,000 of Liquid at today's Liquid price
- Buy ₹20,000 of Bond at today's Bond price

That's 3 separate buys, which together make the "basket".

### 7. Trading at real ₹ prices

The agent **looks** at scaled moves but **trades** at real prices.

**Example:** Gold costs ₹50 and we want ₹60,000 of Gold → we own 60,000 ÷ 50 = **1,200 units**.
Tomorrow Gold is ₹50.50 → those units are worth 1,200 × 50.50 = **₹60,600**.

(V1 allows fractional units, like 1,200.4, to keep things simple.)

### 8. Transaction cost (fee)

Every time we buy or sell, we pay **0.1%** of the amount traded.

**Example:** moving ₹40,000 from Gold to Bond = sell ₹40,000 + buy ₹40,000 = ₹80,000 traded → fee = **₹80**.

**Why:** without fees the agent could jump between baskets every day for free, which isn't realistic. The old notebook had no fees.

### 9. Reward: the SCORE

**Reward = how much the portfolio value changed today, in %, after fees.**

**Example:**
- Yesterday ₹1,00,000 → today ₹1,00,600 → reward **+0.6** → good, do more of this
- Yesterday ₹1,00,000 → today ₹99,500 → reward **−0.5** → bad, avoid this

Over thousands of days, the agent learns which basket **usually** earns positive scores in which situation.

### 10. The 2 main functions

| Function | When it runs | What it does |
|---|---|---|
| `reset()` | start of every episode | ₹1,00,000 all in cash, go to day 10 (the first day with 10 days of history), return the first observation |
| `step(action)` | every day | rebalance to the basket and pay the fee → move 1 day forward → return (observation, reward, game over?, info) |

`info` is extra detail for us, not for the agent: the date, ₹ value, holdings and the fee paid.

### 11. Walking through one `step()`

1. Today's portfolio value = ₹1,00,000
2. Agent picks basket 0 → fee is paid → buy 60/20/20 at today's prices
3. Move to tomorrow → new prices → new value, e.g. ₹1,00,500
4. Reward = (1,00,500 ÷ 1,00,000 − 1) × 100 = **+0.5**
5. If tomorrow is the last day in the data → game over

### 12. Test results (training data, 2020–2022, 736 days)

| Player | Final value |
|---|---|
| Random agent (random basket every day) | ₹86,937 (lost about ₹36,800 to fees!) |
| Always basket 0 (mostly Gold) | ₹1,27,405 |
| Always basket 1 (mostly Bond) | ₹1,22,954 |
| Always basket 2 (mostly Liquid) | ₹1,16,674 |

**Lesson:** switching randomly gets eaten by fees. The real agent has to beat simply holding one basket, or it's useless.

#### In plain words

This table is a **test of the game** (no smart agent yet). I gave ₹1,00,000 to "dumb players" and let them play 2020–2022.

**Everyone, dumb or smart, uses the same 3 baskets, and every basket is a combination:**
- Basket 0 = 60% Gold, 20% Liquid, 20% Bond
- Basket 1 = 20% Gold, 20% Liquid, 60% Bond
- Basket 2 = 20% Gold, 60% Liquid, 20% Bond

"Always mostly Gold" does **not** mean only Gold. It means basket 0 (the 60/20/20 mix) every day.

**The only difference is how they choose:**
- 🎲 Random player → random basket each day → pays fees on every switch → **lost money** (₹86,937)
- 🟡 Basket-0 player → basket 0 every day, never switches → **₹1,27,405** (the best dumb player)
- 🤖 **Smart agent (later)** → picks the best basket for each day

**Example for the smart agent:**
- Gold looks strong → pick basket 0
- Gold looks risky → switch to basket 1 (safer, mostly Bond)

**The goal:** the smart agent must end with **more than ₹1,27,405**. If it doesn't, it's dumber than the basket-0 player and is useless.
